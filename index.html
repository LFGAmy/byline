Byline

your work, sent
as a page.

share work as a page instead of a file, so it stays attributed to you.

scroll down and look at the corners of this page
the problem

a file is a copy, not a view

attach it and a copy exists that you can't see. forwarded, saved, reused, and you've no way of knowing where it went.

fine for most things. less fine for the work you send before anything is signed.

how it works

four layers, one of which actually matters

  1. the token gate. no valid key means the document is never served. not blurred, not hidden behind a modal. never sent. this is the one that stops scrapers.
  2. bot blocking. GPTBot, ClaudeBot, CCBot, PerplexityBot, Bytespider, curl, python-requests and the rest get a 403 before the token check even runs.
  3. noindex everywhere. meta tag, response header, and a robots.txt that names AI training crawlers one by one.
  4. per-recipient watermark. every view is stamped with the name of the person you gave the key to.
the honest part

it cannot stop a screenshot

nobody's can. that's a browser limitation, and any tool that tells you otherwise is lying to you.

so instead of pretending, byline makes every screenshot traceable. that's the difference between a feature and a fix.

give each person their own key. a shared key tells you a leak happened. individual keys tell you whose it was.

setup

about ten minutes

deploy to vercel, set BYLINE_TOKENS to a list of key:Name pairs, drop your document in as index.html, send the link.

revoking is deleting a line and redeploying. the link stops working about a minute later, including for anyone it was forwarded to.
